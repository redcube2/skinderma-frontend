# Internationalisation (i18n) — sk / cs / hu

Status: **content surface only**. No commerce, checkout, payment, shipping,
pricing or CMS schema changes are part of this work. The only infrastructure
piece is the `skinderma.cz` / `skinderma.hu` 301 fold in section 3 — the DNS and
Vercel side of that is still a manual step.

## 1. Locales & routing

| Locale | Language   | URL prefix | `<html lang>` | hreflang | OG locale |
|--------|------------|------------|---------------|----------|-----------|
| `sk`   | Slovenčina | *(none)*   | `sk`          | `sk-SK`  | `sk_SK`   |
| `cs`   | Čeština    | `/cs`      | `cs`          | `cs-CZ`  | `cs_CZ`   |
| `hu`   | Magyar     | `/hu`      | `hu`          | `hu-HU`  | `hu_HU`   |

* Slovak is the default market and is served **without** a path prefix
  (`https://www.skinderma.sk/o-nas`).
* Czech lives under `/cs`, Hungarian under `/hu`
  (`https://www.skinderma.sk/cs/o-nas`).
* `x-default` in the hreflang cluster always points at the Slovak (prefix-less)
  URL.

### Which pages are localised

Real localised pages exist for the Next.js **content** routes only:

```
/            /cs            /hu             → home
/o-nas       /cs/o-nas      /hu/o-nas       → about
/kontakt     /cs/kontakt    /hu/kontakt     → contact + form
/o-skinderme /cs/o-skinderme /hu/o-skinderme → brand facts
/cookies     /cs/cookies    /hu/cookies     → cookies notice
/partnerstvo /cs/partnerstvo /hu/partnerstvo → partnership + form
/blog        /cs/blog       /hu/blog        → blog listing (articles stay Slovak)
```

Everything else — `/obchod`, `/produkt/*`, `/product-category/*`, `/kosik`,
`/pokladna`, `/moj-ucet`, and the legal documents (`/vseobecne-obchodne-podmienky`,
`/reklamacny-poriadok`, `/odstupenie`, `/reklamacia`,
`/ochrana-osobnych-udajov`, `/dodanie`) — is owned by the WooCommerce apex
`skinderma.sk` and is **Slovak-only**. Those links are never locale-prefixed;
in components they are plain `<a href="/…">`, not `next/link` and not run
through `localizedPath()`.

## 2. Architecture

| File | Role |
|------|------|
| `lib/i18n/config.ts` | locale list, `<html lang>` / hreflang / OG maps, `parsePathname()`, `localizedPath()`, `localizedUrl()`, cookie/header names, `SITE_URL` |
| `lib/i18n/routes.ts` | route registry, commerce-prefix guard, vanity-slug alias table, `switchableSegment()` (keeps the language switcher off 404s) |
| `lib/i18n/request.ts` | `getRequestLocale()` / `getRequestRoute()` — read the middleware headers inside Server Components |
| `lib/i18n/metadata.ts` | `buildAlternates()` (canonical + hreflang), `buildPageMetadata()` |
| `lib/i18n/dictionaries/{sk,cs,hu}.ts` | all user-facing copy; `types.ts` is the shared shape. `partnership.form.icoPattern` also carries the accepted company-identifier shape per market (SK/CZ: 8-digit IČO; HU: 11-digit adószám or 10-digit cégjegyzékszám), applied by `components/forms/PartnerContactForm.tsx` after `lib/companyId.ts` strips separators |
| `middleware.ts` | tags every request with `x-skinderma-locale` + `x-skinderma-pathname`; 301s an explicit `/sk` prefix, vanity slugs and mis-prefixed commerce URLs; on the bare `/` only, honours a sticky cookie / `Accept-Language` for `cs`/`hu` |
| `next.config.mjs` | `redirects()` folds `skinderma.cz` / `skinderma.hu` onto `/cs` and `/hu` (section 3) |
| `components/i18n/LanguageSwitcher.tsx` | SK / CZ / HU switch, writes the `skinderma_locale` cookie |
| `components/i18n/LocaleLink.tsx` | `<Link>` that persists the locale cookie before navigating |
| `components/pages/*.tsx` | locale-parametrised views rendered by the `/cs` and `/hu` routes |

The root `app/layout.tsx` reads the locale from the middleware header, sets
`<html lang>`, and emits the localised `<title>` / description / canonical /
hreflang / OpenGraph for the **home** route. Deeper routes set their own via
`generateMetadata` + `buildPageMetadata()`.

### Locale detection on `/`

`middleware.ts` only ever auto-redirects the **bare `/`** entry point, and only
to `/cs` or `/hu`:

1. `skinderma_locale` cookie (set by the switcher) wins.
2. else `Accept-Language`: a `cs*` or `hu*` primary tag redirects; `sk*`, `en*`
   and everything else stay on Slovak.

Deep links and crawlers are never redirected, so a shared `/cs/kontakt` URL
always resolves to Czech. Responses on `/` carry `Vary: Accept-Language, Cookie`.

## 3. skinderma.cz / skinderma.hu -> /cs and /hu

Both ccTLDs are registered (DNS at hostcreators, currently parked and answering
403). They carry no site of their own and are **folded into the localized
sub-paths with a single 301 hop**, so all SEO weight stays on
`www.skinderma.sk` and `/cs` + `/hu` keep the canonical.

The rules live in `next.config.mjs` (`redirects()`, generated by
`ccTldRedirects()`), host-matched with
`has: [{ type: "host", value: "(www\\.)?skinderma\\.cz" }]`. Order inside the
generator is: commerce prefixes, then the content map, then the catch-all.

| From (either ccTLD, with or without `www`) | To (301) |
|--------------------------------------------|----------|
| `/` , `/domu` / `/fooldal`                  | `/cs` resp. `/hu` |
| `/o-nas` , `/rolunk`                        | `/<loc>/o-nas` |
| `/kontakt` , `/kontakty` , `/kapcsolat`     | `/<loc>/kontakt` |
| `/o-skinderme` , `/a-skindermarol`          | `/<loc>/o-skinderme` |
| `/blog` , `/novinky` , `/hirek`             | `/<loc>/blog` |
| `/partnerstvo` , `/partnerstvi` , `/spoluprace` , `/partnerseg` | `/<loc>/partnerstvo` |
| `/cookies` , `/sutik`                       | `/<loc>/cookies` |
| `/obchod`, `/produkt/*`, `/kosik`, `/pokladna`, … | `https://skinderma.sk/<same path>` |
| anything else                               | `/cs` resp. `/hu` (soft landing) |

The vanity slugs mirror `SLUG_ALIASES` in `lib/i18n/routes.ts`, so a link in
either language resolves in one hop rather than two. A unit test asserts that
every route in `ROUTE_SEGMENTS` has a ccTLD mapping — add both together.

### 3a. What still has to happen outside the repo

1. Add `skinderma.cz`, `www.skinderma.cz`, `skinderma.hu`, `www.skinderma.hu`
   to the Vercel project `skinderma-frontend` — **as plain domains, not with
   Vercel's "redirect to primary domain" option**. That option would send
   `skinderma.cz/x` to `www.skinderma.sk/x` (Slovak) and the mapping above
   would never run.
2. Repoint their DNS from hostcreators (`193.163.77.165`) to Vercel.
3. Merge `feature/i18n-sk-cs-hu` — until it is on `main`, `/cs` and `/hu` are
   404 in production and the redirects would land on a missing page.

### 3b. SEO checklist once the domains go live

* `www.skinderma.sk/cs*` and `/hu*` are already `index,follow` with a
  self-referential canonical and the full hreflang cluster — nothing to change
  in the app.
* Submit `skinderma.cz` / `skinderma.hu` in Google Search Console as
  *change of address* targets pointing at the sub-paths.
* `app/sitemap.ts` enumerates every `/cs` + `/hu` content route with the full
  hreflang alternate cluster (`localizedContentEntries()`). `/cookies` is
  deliberately absent while it is still a placeholder.
* Verify each old URL takes exactly one hop.

## 4. Known gaps

* **CZ/HU shipping exists since 2026-09-08** — zone 3 `Česko` and zone 4
  `Maďarsko`, each with a 6,00 € flat rate (`tax_status: none`, so the customer
  pays exactly 6,00 €) plus free shipping over `min_amount: 162.60`. Selling to
  CZ/HU was already enabled (`woocommerce_specific_allowed_countries`).
  `tax_display_cart` is `excl`, so WooCommerce compares that threshold against
  the **net** subtotal — 162,60 € net is 200,00 € with 23% VAT, which is what
  the `home.skinia` copy promises.
* **Paid rates are hidden once free shipping applies** by
  `docs/wp-snippets/hide-paid-shipping-when-free.php`. That snippet lives in
  WordPress (Code Snippets plugin), not in this app — the file here is only its
  reviewable home, so check it is actually installed before assuming the
  behaviour is live.
* **The Slovak zone has no free shipping** (deliberate — it is configured as
  the owner wants it), so the Slovak `home.skinia` copy no longer promises one:
  it names the real options (SPS Balíkovo 3 €, free local pickup) and keeps the
  Skinia software offer. CZ/HU keep the free-shipping claim — there a real
  `free_shipping` rate backs it.
* **The frontend shows gross prices, the WooCommerce cart shows net.** Both
  `tax_display_shop` and `tax_display_cart` are `excl`, while `lib/woocommerce.ts`
  applies `priceWithVat()`. A customer sees 142,80 € here and 116,10 € in the
  cart. Pre-existing and out of scope for i18n, but worth a look for B2C.
* **`/cookies` is a placeholder** in all three locales — noindex and out of the
  sitemap until it carries a real notice.
* **`/dodanie` is Slovak-only** and is linked from the CZ/HU footer. Unlike the
  legal documents (deliberate WP rewrites) this page is ours and could be
  localized.
* **HU copy was translated from Slovak, not keyword-mapped.**
  `contexts/skinderma.md` asks for HU product/order intent to be mapped
  separately before writing Hungarian copy.

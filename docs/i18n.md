# Internationalisation (i18n) — sk / cs / hu

Status: **content surface only**. No commerce, checkout, payment, shipping,
pricing, CMS schema, DNS or deployment changes are part of this work.

## 1. Locales & routing

| Locale | Language   | URL prefix | `<html lang>` | hreflang | OG locale |
|--------|------------|------------|---------------|----------|-----------|
| `sk`   | Slovenčina | *(none)*   | `sk`          | `sk-SK`  | `sk_SK`   |
| `cs`   | Čeština    | `/cs`      | `cs`          | `cs-CZ`  | `cs_CZ`   |
| `hu`   | Magyar     | `/hu`      | `hu`          | `hu-HU`  | `hu_HU`   |

* Slovak is the default market and is served **without** a path prefix
  (`https://www.skinderma.sk/o-nas`).
* Czech lives under `/cs`, Hungarian under `/hu`
  (`https://www.skinderma.sk/cs/o-nas`).
* `x-default` in the hreflang cluster always points at the Slovak (prefix-less)
  URL.

### Which pages are localised

Real localised pages exist for the Next.js **content** routes only:

```
/            /cs            /hu             → home
/o-nas       /cs/o-nas      /hu/o-nas       → about
/kontakt     /cs/kontakt    /hu/kontakt     → contact + form
/o-skinderme /cs/o-skinderme /hu/o-skinderme → brand facts
/cookies     /cs/cookies    /hu/cookies     → cookies notice
/partnerstvo /cs/partnerstvo /hu/partnerstvo → partnership + form
/blog        /cs/blog       /hu/blog        → blog listing (articles stay Slovak)
```

Everything else — `/obchod`, `/produkt/*`, `/product-category/*`, `/kosik`,
`/pokladna`, `/moj-ucet`, and the legal documents (`/vseobecne-obchodne-podmienky`,
`/reklamacny-poriadok`, `/odstupenie`, `/reklamacia`,
`/ochrana-osobnych-udajov`, `/dodanie`) — is owned by the WooCommerce apex
`skinderma.sk` and is **Slovak-only**. Those links are never locale-prefixed;
in components they are plain `<a href="/…">`, not `next/link` and not run
through `localizedPath()`.

## 2. Architecture

| File | Role |
|------|------|
| `lib/i18n/config.ts` | locale list, `<html lang>` / hreflang / OG maps, `parsePathname()`, `localizedPath()`, `localizedUrl()`, cookie/header names, `SITE_URL` |
| `lib/i18n/routes.ts` | route registry, commerce-prefix guard, vanity-slug alias table, `switchableSegment()` (keeps the language switcher off 404s) |
| `lib/i18n/request.ts` | `getRequestLocale()` / `getRequestRoute()` — read the middleware headers inside Server Components |
| `lib/i18n/metadata.ts` | `buildAlternates()` (canonical + hreflang), `buildPageMetadata()` |
| `lib/i18n/dictionaries/{sk,cs,hu}.ts` | all user-facing copy; `types.ts` is the shared shape |
| `middleware.ts` | tags every request with `x-skinderma-locale` + `x-skinderma-pathname`; 301s vanity slugs and mis-prefixed commerce URLs; on the bare `/` only, honours a sticky cookie / `Accept-Language` for `cs`/`hu` |
| `components/i18n/LanguageSwitcher.tsx` | SK / CZ / HU switch, writes the `skinderma_locale` cookie |
| `components/i18n/LocaleLink.tsx` | `<Link>` that persists the locale cookie before navigating |
| `components/pages/*.tsx` | locale-parametrised views rendered by the `/cs` and `/hu` routes |

The root `app/layout.tsx` reads the locale from the middleware header, sets
`<html lang>`, and emits the localised `<title>` / description / canonical /
hreflang / OpenGraph for the **home** route. Deeper routes set their own via
`generateMetadata` + `buildPageMetadata()`.

### Locale detection on `/`

`middleware.ts` only ever auto-redirects the **bare `/`** entry point, and only
to `/cs` or `/hu`:

1. `skinderma_locale` cookie (set by the switcher) wins.
2. else `Accept-Language`: a `cs*` or `hu*` primary tag redirects; `sk*`, `en*`
   and everything else stay on Slovak.

Deep links and crawlers are never redirected, so a shared `/cs/kontakt` URL
always resolves to Czech. Responses on `/` carry `Vary: Accept-Language, Cookie`.

## 3. Future 301 mappings — skinderma.cz -> /cs, skinderma.hu -> /hu

These domains are **not** wired yet. When they are pointed at this deployment
(or a redirect service in front of it), add host-based 301s so the standalone
ccTLDs fold into the sub-paths and the sub-path stays the SEO canonical.

### 3a. Apex/domain-level redirects (do these at the edge / DNS host)

| From (old site)                | To (301, permanent)                     |
|--------------------------------|-----------------------------------------|
| `https://skinderma.cz/`        | `https://www.skinderma.sk/cs`           |
| `https://www.skinderma.cz/`    | `https://www.skinderma.sk/cs`           |
| `https://skinderma.hu/`        | `https://www.skinderma.sk/hu`           |
| `https://www.skinderma.hu/`    | `https://www.skinderma.sk/hu`           |

### 3b. Path-level redirects (preserve deep links)

Map each old-domain path to the matching localised sub-path. Where the old
site used a localised vanity slug, redirect to the canonical route
(the alias table in `lib/i18n/routes.ts` mirrors these):

| From `skinderma.cz/<path>`        | To `www.skinderma.sk/cs/<path>` |
|----------------------------------|---------------------------------|
| `/` , `/domu`                    | `/cs`                           |
| `/o-nas`                         | `/cs/o-nas`                     |
| `/kontakt` , `/kontakty`         | `/cs/kontakt`                   |
| `/o-skinderme`                   | `/cs/o-skinderme`               |
| `/novinky` , `/blog`             | `/cs/blog`                      |
| `/spoluprace` , `/partnerstvi`   | `/cs/partnerstvo`               |

| any product / shop / cart path   | `https://skinderma.sk/<same>`   (Slovak apex owns commerce) |

### 3c. Where to implement

* **Preferred:** at the DNS/CDN host for `skinderma.cz` / `skinderma.hu`
  (Cloudflare Bulk Redirects, hostcreators redirect rules, or a tiny Vercel
  project with `redirects()` for those domains only).
* If those domains are added as extra domains on **this** Vercel project,
  add host-conditioned rules in `next.config.mjs` `redirects()` using
  `has: [{ type: "host", value: "(www\\.)?skinderma\\.cz" }]` and rewrite the
  destination to `https://www.skinderma.sk/cs/:path*`.
* Keep them **301 / permanent**. Verify each old URL has exactly one hop.

### 3d. SEO checklist once domains go live

* `www.skinderma.sk/cs*` and `/hu*` are already `index,follow` with a
  self-referential canonical and the full hreflang cluster — nothing to change
  in the app.
* Submit `skinderma.cz` / `skinderma.hu` in Google Search Console as
  *change of address* targets pointing at the sub-paths (GSC treats sub-paths
  fine as long as the redirect + canonical agree).
* `app/sitemap.ts` already enumerates every `/cs` + `/hu` content route with the
  full hreflang alternate cluster (`localizedContentEntries()`), so no separate
  per-locale sitemap is needed. Re-check it if new localized routes are added.
